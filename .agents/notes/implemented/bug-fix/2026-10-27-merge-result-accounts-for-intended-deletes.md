# Agent Note: 预合并检查认得「有据可查的删除」

Status: implemented

## Problem

`scripts/check-merge-result.mjs` 只用一条判据：base 的路径在结果里还在不在。不在了
就 `exit 1`。可「路径不在了」有两种来源，脚本分不出来：

- 这次改动真的想删掉它；
- 合并动作把一棵好树变成了「没了」（回退，`b3ffe400` 那种）。

#294 是第一种：PR 有意删 `apply-patch.ts` 与它的测试，CI 照红。脚本末尾那句
「If the deletion is intended, say so in the PR description」从落地起就只是文案，
没有任何代码读它。

而回复里原本打算用的「`head` 有多父就允许删」在 CNB 上是零信息量：CNB 的
`check-merge-result-cnb.mjs` 恒造合并提交，等于把这条检查关掉。更关键的是，判据换成
方向之后**同一个删除会按「有没有多一个父」翻面**——历史完全相同，只是目标分支有没有
往前走，结论就相反。那是我们要修的不对称，不是要写进规格的东西。

## Decision

分两层。第一层仍是「base 的路径在结果里还在不在」（`ls-tree` 逐路径比），不改。
第二层判「这次删除有没有证据」，两个来源，任一即可：

- **`deletes: <path>` 白名单**：PR 描述或 PR 自己的提交消息里逐条列出。只认点名的
  路径，`deletes: *` 不算数。
- **合并提交那一跳里的 `D`**：结果提交的父多于一个时，看 `git diff --raw -M -l0
  HEAD^1 HEAD`，状态为 `D` 的路径算「这次合并删的」。显式 `-M -l0` 是为了把改名压在
  `R` 上——`R` 不认，改名照旧红。`git show --raw` 默认会做改名检测，别在那里看 `D`。

单父提交只有第一条路：那一跳就是提交自己，回退型的提交也是 `D`，方向说明不了意图。
这不是「按合并提交放宽」，是「按删除有没有证据放宽」——合并提交那一跳之所以能当证据，
是因为它是 `git merge` 写的，方向由 git 保证，而**回退不会在那一跳留下 `D`**。

输入全部由调用方传：`--description-file`（PR 描述写到临时文件）与 `--commit`（提交消息
的来源）。脚本仍然只读 git 对象加这个文件，不联网、不装依赖。

## Consequences

- #294 那个形状（CNB 折出来的合并提交里带删除）自然放行，不必写清单。
- `b3ffe400` 那种「整棵树换回旧快照」仍然红：合并那一跳只有 `M`/`A`，没有 `D` 可认。
- 删除型 PR 现在有两条路：写清单（有据可查），或者让合并那一跳自己作证（CNB/GitHub
  的默认形态）。两者都不成立时照旧红，文案改成让人写 `deletes:`，不再让人去求人放行。
- GitHub 侧 `--commit` 指到 `pull_request.head.sha`：结果提交是 GitHub 造的合并提交，
  `deletes:` 只会写在 PR 自己的提交上。

## Alternatives considered

- **只按「`head` 有多父」放宽（原 C 方案）。** 看着最贴题，实测零信息量：CNB 上恒真，
  等于关掉检查；GitHub 上又会让 `b3ffe400` 变绿。否决。
- **只认 `git diff --raw` 的 `D`，不要白名单（原 B 方案单独用）。** 它会把改名的旧路径
  读成 `R` 放过去，而改名本质上也是删掉旧路径；现有单测 `a rename is reported, not
  waved through` 钉的就是这条。要么先决定改名放不放，要么显式 `-M -l0` 且只认 `D`。
  采用后者的同时保留白名单：白名单才是「意图被记下来」的那一条。
- **用 `rev-list --ancestry-path` 找 PR 的起点，证明「PR 之间没人动过这个路径」。**
  这就是回复里那个 a) 方案，能止血但答非所问：它证明的是「没人动过」，不是「想删」。
  而且「`^1` 是不是新父」这个分支本身就是那条不对称。改成合并提交自证之后整段不需要了。
- **判定脚本自己调 CNB / GitHub API 读 PR 描述。** 脚本的价值之一是「只读 git 对象、
  装都不用装」，为了读一段文本引入网络与凭据不值。调用方写文件传进来即可。
- **不放宽，只改文案（原 D 方案）。** 最省事，但意味着每个删除型 PR 都红一次、都靠人
  跳过，绿不绿取决于谁值班。

`scripts/check-merge-result.test.mjs` 覆盖：白名单放行、白名单逐条（`*` 不算）、合并提交
自证放行、合并提交里的回退仍红、合并提交里的改名仍红、同一删除在快进与合并两种形态下
结论一致（差别只能由「那一跳是不是合并动作」解释）。`check-merge-result-cnb.test.mjs`
覆盖 `CNB_PULL_REQUEST_DESC` 落地成文件这条线。
