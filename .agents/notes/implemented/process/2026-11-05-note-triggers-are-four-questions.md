# Agent Note: 笔记的触发条件是四问，由一个不失败的提醒兜底

Status: implemented

## Problem

`.agents/notes/` 有 117 篇，触发条件却不好使：SKILL 要求「非平凡改动必须写」，并列了
六个领域（行为 / 架构 / 跨文件契约 / 流程与工具链 / 测试策略 / 落盘格式）。模型读完
六条会犹豫，犹豫的成本立刻发生，写笔记的收益要几周后才有人兑现，于是倾向不写。

数据：近 40 个非 merge 提交里，改到 `packages/*/src` 的有 31 个，带笔记的只有 10 个。
漏掉的多是结构性改动——「live theme 传给 renderer」「模块接管 ctrl+t」「消息类型做成
codec 注册表」，这些恰恰是跨文件契约，按六领域该写。反倒是 4 个「事后补 note」
（`docs(ai): 补 note`、`docs(notes): 同步过时的笔记事实`）在证明流程本身有人认。

## Decision

**触发条件换成四个能用 diff 回答的否命题，任一命中就写**（SKILL §文首）：

1. 「行为没变」说出口能被指着 diff 骂吗——默认值、状态流转、错误形状、时序。
2. 有下游依赖它吗——跨文件 / 跨包 / 跨进程 / 跨版本的调用方，导出面也算。
3. 半年前的我照这篇笔记能做出同样的选择吗——被否掉的路、选 A 不选 B 的理由。
4. 它改了别人读文件的方式吗——配置 / schema / wire / 落盘格式。

四问都答「否」就不写，而且「答不出来」不算命中：每条的「是」与「否」都要有 diff 上的
依据。这是与「重大」的关键差别——「重大」没有可执行的边界，同一个改动作者当修 bug、
评审当契约变更，模型只能靠运气。

**再加三条不需要判断的机械触发器**，全部作用在已经发生的事实上：提交里带回归测试 →
`bug-fix`；同一个「为什么」被回答了第二次 → 落盘；PR 描述写到了要分节 → 回查四问。

**提醒做成不失败的门**：`scripts/check-agent-notes.mjs` 在 diff 够大（`packages/*/src`
≥ 80 行，`packages/{agent,coding-agent}/src` ≥ 40 行）或新增了回归测试、且 diff 里一行
`.agents/notes/` 都没碰时，打印提示，退出码恒为 0。挂在 `.husky/pre-commit` 与 CNB 的
`pull_request.target` 流水线上（`--base origin/main`）。

## Why a reminder and not a gate

把它变成失败只有一种实现方式：拿行数当代理。行数和「值不值得记」的相关性很弱——
一次 200 行的机械 rename 该静音，一个 3 行的默认值改动该写。让脚本替人判，等于把
噪音变成阻断，很快所有人都会学会绕过它。

所以脚本只答一个它能答的问题：「这次 diff 大到不像机械改动，你回头看过四问了吗」。
剩下的一律归人。代价是它可以被忽略——这正是目的：连续被忽略几十次而没人写，就是
「规则本身不成立」的证据，那时再谈收紧或放弃，而不是先假设规则成立。

## Alternatives considered

**每个改动都记**。笔记会退化成 changelog：检索价值归零，117 篇现在已经在「不重不漏」
的边界上，按提交数乘上去会失控。

**完全交给模型判断**。就是改动前的现状，19% 的覆盖率（改 `packages/*/src` 的 31 个
提交里 10 个带笔记）已经是结论。

**六领域清单再补例子**。清单本身没错，错在它要人在写之前先做一次分类。四问是分类
之后的结果，回答成本更低，而且答案能落到 diff 上。

**软警告里带上「该写哪一篇」**。判不了。目录 / class / lifecycle 都是语义判断，
猜错的提示比没有提示更坏——它会训练人无视提示。

## Consequences

- AGENTS.md 原来完全没提笔记这件事，现在有了一节；不读 SKILL 的人也能看到触发条件。
- 提醒默认静音意味着它不可能自己变准。要么有人看提示，要么这条改动就该被推翻，
  两者都需要观测，而不是再加一层规则。
- 阈值（80 / 40）没有依据，是「先低到能看见噪声」的估计值。改数字请连 note 一起改。
- `check:agent-notes` 不进 `pnpm run check`：那套命令的约定是「出错就红」，
  一个恒返回 0 的步骤放进去只会让人以为它检查了什么。
- 推送侧的 `check-commit-trailers` 是同类先例：CI 只报告不拦截，因为拦截了也修不了。
